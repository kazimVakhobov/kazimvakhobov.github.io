# portfolio

Personal portfolio and website of Kazim Vakhobov — Senior Frontend Engineer.

Built with [Astro](https://astro.build). Static output, English only — one home
page plus a long-form write-up on its own URL.

## Development

```bash
npm install
npm run dev      # http://localhost:4321
npm run check    # type check
npm run build    # static output in dist/
npm run preview  # serve dist/ locally
```

## Content

Everything editable lives in two places.

### 1. Resume and interface text — `src/data/site.json`

Every string on the site lives in this one file: metadata, navigation, sidebar,
hero, about, experience, education, skills, contact, footer. Components import it
directly (`import site from '../data/site.json'`), so there is no dictionary layer
to keep in sync.

Array sections (`experience.items`, `skills.groups`, …) can hold an empty template
entry — copy one and fill it in. Entries whose main field (`role`, `degree`, `name`,
`label`) is still empty are not rendered, so blank templates stay invisible on the site.

### 2. Projects — `src/data/projects.json`

Projects are cards in the `Projects` section of the home page; there are no
separate project pages. One object per project, and the order in the file is the
order on the page:

```json
{
  "id": "my-cli",
  "kicker": "Open source · developer tooling",
  "title": "my-cli",
  "description": "One or two sentences: what it does and why it exists.",
  "tags": ["Node.js", "CLI"],
  "links": [
    { "label": "Source code", "href": "https://github.com/…", "icon": "github" },
    { "label": "Website", "href": "https://…", "icon": "external" }
  ]
}
```

Every key is required — leave a string empty or an array empty when there is
nothing to show, and it simply is not rendered. `icon` is a name from
`src/components/Icon.astro` (`github`, `external`, `play`, `docs`, `npm`, …);
an unknown name falls back to the external-link icon.

### 3. The write-up — `src/pages/agents-need-context-not-access.astro`

A long-form page with its own URL, so the link can be shared on its own:
`/agents-need-context-not-access/`. The prose lives in the page file; only the
shared bits — slug, title, description, date, reading time, and the teaser shown
on the home page — live in `site.json` under `writeup`, so the card and the page
cannot drift apart.

The page leans on diagrams rather than prose — six of them, as components in
`src/components/diagrams/`, wrapped in `Figure.astro` (label, frame, caption).
All hand-written CSS and inline SVG: no diagram library, no runtime, and both
themes come from the same tokens as the rest of the site.

Four of them are flow charts sharing `flow.css` (boxes, edges, legend) and
`FlowDefs.astro`, which emits the arrowheads once per page — SVG markers are
addressed by document-level id, so every chart on the page points at the same
three. The palette is three colours and no more: grey for the ordinary path,
`--ok` for what passes, `--accent` for what stops and asks a person.

Things to know before editing one:

- **Scoped styles do not reach inside a child component.** A rule like
  `.foo svg { … }` will not style an `<Icon>`; write `.foo :global(svg)` instead.
- **A diagram that is one fixed-width SVG** gets `<Figure scroll>`: below its
  `min-width` it scrolls inside its frame rather than shrinking its labels into
  illegibility, and the frame fades at the right edge while there is more to see.
- **A diagram that reflows** (`Tradeoff`) sizes itself with `@container`, not
  `@media`. The figures live in a ~565px column inside a 1500px window, so a
  viewport query would switch on the wide layout where there is no room for it.
- **Astro drops the space before an inline element that starts a line.**
  `… written up as\n<a href={ADR}>` renders as `as<a…>`. Keep `<code>`, `<a>` and
  `<strong>` on the same line as the word before them.

The social preview is a committed PNG, `public/og/*.png`, generated by
`node scripts/make-og.mjs` — run it by hand when the title or the design changes.

## Photos

Two files, because the two places want different crops. `src/assets/avatar.jpeg`
is the waist-up portrait and is only the home page's `og:image`;
`src/assets/headshot.jpeg` is a 318×318 crop of it, taken at `(193, 16)` with the
eye line near 40% of the height, and is what the sidebar shows. Cropping in the
file rather than with a CSS transform is what keeps the 112px avatar sharp —
Astro's derivatives then hold the face instead of the whole body.

## Routing

The site is the home page `/`, the write-up at
`/agents-need-context-not-access/`, and a `404`. Nav items are anchors into the
sections of the home page, listed in `src/components/Header.astro` in document
order — with seven of them the header is tight between 981px and 1100px, which is
why it loses some horizontal padding there. The sitemap is generated
automatically.

## Deploy

**GitHub Pages**, built by `.github/workflows/pages.yml` on every push to
`master` — `npm ci`, `npm run build`, then `dist/` is uploaded and deployed.
Work happens on `dev` and reaches `master` through a pull request, so nothing
deploys by accident.

The repository is the user site, `kazimvakhobov.github.io`, which is what puts
the site at the root of that host rather than under `/portfolio/`. Renaming it
would mean setting `base` in `astro.config.mjs` and fixing every absolute path.

The custom domain is `kazimvakhobov.com`, and `public/CNAME` carries it into
every build — the Actions deployment serves exactly what the artifact contains,
so the file has to be in the source rather than only in the repository settings.
Once the domain is set, `kazimvakhobov.github.io` redirects to it.

DNS lives at Namecheap. The apex needs four A records to GitHub's Pages
addresses — `185.199.108.153`, `.109.153`, `.110.153`, `.111.153` — and `www`
needs a CNAME to `kazimvakhobov.github.io`. The same zone already serves
`detent.kazimvakhobov.com` the same way.

Alternatives, same output:

- **Cloudflare Pages** — connect the repo, build `npm run build`, output `dist`,
  Node 22; add both the apex and `www` under Custom domains.
- **Netlify** — build `npm run build`, publish `dist`, custom domains on the free plan.
- **Own VPS** — `npm run build`, copy `dist/` to the server, serve it with nginx:

  ```nginx
  server {
      server_name kazimvakhobov.com;
      root /var/www/portfolio;
      index index.html;
      location / {
          try_files $uri $uri/ $uri/index.html =404;
      }
      error_page 404 /404.html;
  }
  ```

The site URL is set in `astro.config.mjs` (`site`). It is used for canonical links,
`hreflang` and the sitemap — update it if the domain changes.
